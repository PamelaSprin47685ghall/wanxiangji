# LEMMA
1. [根 AXIOM: 10; 根 LEMMA: 7] 一次请求的内容先作为一个确认批次落账，落账成功后才发出。
    - 推理：根 LEMMA 7 说请求发出即确认；根 AXIOM 10 要求已确认的内容在崩溃后仍在。先发后落账，两步之间崩溃，就有已确认却不在的内容；先落账后发，两步之间崩溃，只多出一条已落账、未发出的内容，用户重发即可。
2. [根 AXIOM: 10, 14; 根 LEMMA: 2, 7] 停止或中断时已显示的生成内容，作为下一次请求的上下文发出，从而按根 LEMMA 7 得到确认；此前不另设持久形态。
    - 推理：根 AXIOM 10 要求中断不吃掉已生成的内容，根 AXIOM 14 允许随时停止。为半截回复另设一种落盘，同一段文字就有两个出处，违反根 LEMMA 2。下次请求前崩溃，丢的正是根 AXIOM 10 允许丢的尾部。
3. [根 AXIOM: 12] 访问权是可吊销的凭据，吊销对已建立的连接立刻生效；没有凭据时只开放取得凭据的最小入口。
    - 推理：只拦新连接、不断旧连接，吊销就不算生效。首次接入要有一条路，这条路之外不能有别的匿名入口。
4. [根 AXIOM: 15; 根 LEMMA: 2] 配置只有一个权威出处，界面修改与手改写同一处；配置无效时指出哪一项错，并按上一份有效配置运行。
    - 推理：根 LEMMA 2 排除第二份手写配置。根 AXIOM 15 要求错误可行动：拒绝启动或静默生效，都不告诉用户下一步。

# SPEC
1. [根 AXIOM: 10, 14; 根 LEMMA: 4, 5, 7] 停止后已确认的内容不变；停止与流结束并发时，系统只产生一个符合契约的结果。
    - 证明：用受控的异步测试驱动模型流，分别注入正常结束、提前停止、停止后迟到的数据、停止与完成并发、连接中断；检查已确认内容不丢、不重，最终结果符合预先定义的竞争规则。再注入流式中途崩溃，检查恢复后流式尾部至多整段缺失、不出现半条。
2. [LEMMA: 1] 假服务商收到的每个请求，其内容都已在账本中。
    - 证明：在三个点注入进程崩溃：落账前、落账后发出前、发出后。恢复后检查：落账前崩溃，账本无该批次，服务商收到 0 次；落账后发出前崩溃，账本有完整批次，服务商收到 0 次，用户重发后收到 1 次且账本不出现重复内容；发出后崩溃，账本有完整批次，服务商收到 1 次。三种情形都不出现服务商收到而账本缺失的内容。
3. [LEMMA: 2] 停止前已显示的内容进入下一次请求。
    - 证明：流式中途停止，再发一条消息，检查发给假服务商的上下文包含停止前已显示的全部文字。
4. [LEMMA: 3] 吊销立刻生效。
    - 证明：建立连接后吊销凭据，检查连接在规定时限内关闭、此后用该凭据的请求被拒；无凭据的请求只能到达取得凭据的入口。
5. [根 AXIOM: 17] 工具调用不等待授权。
    - 证明：模型流中发起对假工具的调用，检查调用在没有任何用户动作时执行，全程不出现授权类消息。
6. [LEMMA: 4] 配置错误可定位、不中断。
    - 证明：写入一份错误配置，检查提示指名出错项，运行状态与上一份有效配置一致。
